# GoreeCloud Search security and authority boundaries

**Development. No operational security or Production acceptance granted.**

1. The supplied wrapper `scripts/run-private.sh` requires a 32+-character secret and refuses public-interface, public-instance, GET, and unproxied-image overrides. It selects the loopback-only configuration.
2. JSON in the local profile is **not authenticated**. Never expose this profile to untrusted networks. A public GoreeCloud API needs separately verified Identity, Privacy Shield authority and API limits.
3. The private profile allowlists **eleven category adapters in three provider families**: Brave Search (`brave`, `brave.images`, `brave.videos`, `brave.news`), Startpage (`startpage`, `startpage images`, `startpage news`) and Qwant (`qwant`, `qwant images`, `qwant videos`, `qwant news`). Other inherited providers are excluded. Search and preview validate explicit source names before dispatch. Provider inclusion is not independent indexing, anonymity or evidence of upstream request success.
4. Before public deployment, independently validate SSRF/XSS protections, rate limiting/Valkey, HTTPS and reverse proxies, secret management, query redaction, logging/retention, uptime, rollbacks and live security/privacy gates.
5. Glaze is presentation-only: it must not imply consent, permission, authorized indexing, Identity state, Wardveil rules, or Production approval.
6. The private mode rejects external bangs and first-result navigation before provider dispatch; unexpected redirects are denied after a search. Explicit user clicks on result links can still disclose information to destinations.
7. Raw query length is checked before parsing operators. The submitted search remains POST-only, with selection caps before network dispatch. Private mode returns uncached 404 responses for direct `/opensearch.xml` and `/autocompleter` GET endpoints, blocking alternate browser-discovery and suggestion routes even if a client bypasses the interface.
8. Private mode rejects serialized GET and nonempty POST preference imports before decoding; upstream normally auto-applies shared settings links, which can silently change which providers a user searches. Ordinary local Preferences forms remain available and uncached. Private navigation never copies shared preference tokens into links.
9. Main clickable search results use a bounded HTTP(S) URL-scheme and authority guard in private HTML and JSON. This does not constitute complete safety validation of result template secondary links, embedded media, image proxies, outbound HTTP requests or the sites users choose to visit.
10. The represented-source display counts selected engine names carried on accepted primary result objects for this page only. It does not authenticate the provider, establish that an HTTP request succeeded, measure request volume, or cover discarded unsafe results, answers or infoboxes. This is a transparent result-label inventory, not a provider audit.
11. Private `POST /preview` is a no-network query-selection inspection. It parses the real search input with the same raw-size, fanout and redirect guards and creates no SearXNG provider executor. Its JSON mode with `format=json` deliberately omits raw query text; the HTML view retains the submitted query only in the protected POST-continuation form. Continuing or selecting a single source requires a separate explicit POST that may send the terms to configured third-party providers. This is not an independent provider health or privacy guarantee. Unsupported GET requests to `/preview` receive uncached 405, and the route is disabled outside the private profile.
12. Startpage remains subject to upstream proof-of-work / CAPTCHA blocking. GoreeCloud selects it as part of the approved **three-provider** lineup; startup registration does not prove that any provider, including Qwant, is reachable. Never silently substitute a different provider on failure.
13. The private parser treats explicit `engines=` choices as an exact validated subset to prevent SearXNG's category+engine union from widening query disclosure. Bang/engine conflicts fail closed. Web, Images, Videos and News tabs submit via POST and select only per-category approved variants (at most three families; Videos: Brave and Qwant). A Startpage-only preference disables Videos rather than silently substituting another source. Browser-local preferences and pagination/header resubmission preserve validated selection.
14. Inherited upstream CI/release automation remains disabled. Bounded source/runtime and synthetic browser tests are not Production or official Glaze acceptance.
15. Provider diagnostics for **Brave Search, Startpage and Qwant** must not expose request URLs, query-bearing POST data, cookies, or provider tokens. Live October 2026 testing exposed a query-bearing URL in the shared upstream network failure log. Both failure and debug network log paths have now been changed to record method/status without the request URL; a regression test and a subsequent live HTTP 429 check confirm this specific fix. Redaction of all remaining outbound paths, exception handlers and production telemetry still requires security qualification.
16. The opt-in `scripts/provider_health_probe.py` supports **all three approved Web providers** and a legacy two-provider choice, uses fixed synthetic terms against an already-running loopback-only Development service, and **sends no requests without `--allow-provider-egress`**. It disables environment proxies and rejects redirects. A local probe does not prove upstream provider privacy or public deployment readiness.
17. The inherited `manage webapp.run` launcher originally hardcoded `GRANIAN_HOST=::` and `SEARXNG_DEBUG=1`, overriding the private script's loopback requirement. The development wrapper now disables debug/hot reload and `manage` respects `SEARXNG_BIND_ADDRESS` when supplied. Launcher contract tests guard against this regression. Static checks and browser CI do not replace an actual socket-binding audit before provider traffic or deployment.

18. Startpage explicit blocking at https://cdn.startpage.com/sp/cdn/error-pages/blocked.html is classified as provider access denied rather than a successful empty response. This does not bypass its block or authorize an alternate engine. Synthetic offline adapter tests cover known and spoofed locations.
19. A real pinned Granian 2.8.4 listener is tested on an ephemeral 127.0.0.1-only socket with no provider traffic and a clean process-group shutdown; GitHub Actions runs the same check independently. An additional October 2026 **real loopback Granian HTTP POST** to the Startpage Web adapter retrieved 10 live results and used uncached JSON, with verified socket binding and cleanup. This does not qualify reverse proxies, public networks, managed-wrapper deployment, upstream provider reliability or production acceptance.
